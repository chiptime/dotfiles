# tiktok-ingest GPU lease (Stability track S2) — ODD feature document

Objective: one owner for the Whisper/Ollama GPU swap, plus a persisted lease marker so a later run restores a Whisper service left stopped by a dead run.
Branch: `feat/tiktok-gpu-lease` (from master `ba5af32`). Delivery: ask-on-risk; one work-unit commit per task. Test runner: stdlib `unittest` (`env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=ai/tiktok-ingest/src python3 -m unittest discover -s ai/tiktok-ingest/src/tiktok_ingest/tests -t ai/tiktok-ingest/src`, baseline 960 OK).

## Specs

- S1 — Single owner (ROADMAP "S2 — One owner for the GPU swap", verbatim): "Introduce a single `gpu_lease` context manager that stops Whisper, verifies free VRAM, and restores Whisper in `finally`. Every vision attempt and swap retry runs inside it, replacing the per-branch restoration in `guided.py` and `collection_run.py`."
- S2 — One health wait: the two post-restore readiness waits (`guided._wait_for_whisper_health`, `collection_run._wait_whisper_healthy_for_retry`) become one implementation with the same bounds (immediate first probe, ~1 s interval, 60 s deadline) and the same operator feedback where it exists today.
- S3 — Persisted lease marker: `<state root>/active_gpu_lease.json`, written atomically BEFORE the Whisper stop is issued, holding the owner PID plus process start time (PID-reuse safe), timestamp and the verified Whisper identity snapshot (name, image, identity env). Removed only after a verified healthy restore. Never holds secrets (only identity env keys already allowed by `WHISPER_IDENTITY_ENV_KEYS`).
- S4 — Startup reconcile (user decision L3 "1.b"): before any new GPU work, if a marker exists whose owner process is dead and Whisper is stopped with the SAME identity as the snapshot, restore it automatically under the restore authorization granted by the original run (no new prompt), with identity verification, exactly one start and the bounded health wait; report it. Whisper already running → just clear the marker. Identity mismatch, container missing, or any probe failure → fail closed: no mutation, explicit report with recovery instructions.
- S5 — Interrupted-stop case (user decision L3 "2.si"): within the interrupted process the existing rule stays ("interruption lands inside the stop itself: then the stop result is UNKNOWN, NO restore is attempted"); at the next start the marker proves the stop was ours, so S4 applies to it as well.
- S6 — Concurrency guard (assumption, accepted as default): a marker whose owner process is alive blocks opening a new GPU window in another process; explicit refusal, no mutation.
- S7 — Behaviour preserved: every existing message, report field and state (`whisper_restore_failed`, `cleanup_notes`, `hard_stop_reason`, `blocked_global`, `interrupted_unknown`, "was STARTED", "health is UNKNOWN", "did not become healthy within 60s", "waiting for Whisper readiness", "NO restore was attempted", ...) stays identical; the existing suite passes without editing assertions. Exactly-one-start and no-restore-on-interrupted-stop rules hold.
- S8 — Docs: OPERATIONS.md describes the marker, the reconcile and the concurrency guard; ROADMAP.md marks S2 done.
